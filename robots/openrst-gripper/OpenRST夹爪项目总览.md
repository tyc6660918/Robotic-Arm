# OpenRST 绳驱夹爪集成系统

## 1. 区域用途

OpenRST 夹爪区域包含三自由度绳驱手术器械集成系统，作为遥操作手术训练平台中 Dummy 六轴机械臂的末端执行器。本区域桥接开源学术硬件（名古屋大学长谷川实验室）与定制化基于 STM32 的控制电子系统，涵盖机械 CAD 文件、运动学模型、固件设计规范以及仿真集成。

## 6. 使用说明

**控制架构（已设计）：**

OpenRST 夹爪通过具有独立电机驱动的三自由度绳驱机构控制：

1. **关节配置：**
   - 关节 1（俯仰）：腕部俯仰旋转
   - 关节 2（左钳口）：独立左钳控制
   - 关节 3（右钳口）：独立右钳控制

2. **串口协议（已设计但未实现）：**
   ```
   命令格式：P<pitch>U<upper>L<lower>
   示例：P45.2U10.5L10.5
   ```
   - 与 Dummy 臂分离的独立串口（未集成 CAN 总线）
   - 采用浮点角度值的 ASCII 协议

3. **控制模式（已设计）：**
   - 位置控制（PID，1kHz）
   - 速度控制（PID，5kHz）
   - 电流控制（PID，20kHz，最内环）

4. **标定（已设计）：**
   - 基于光电传感器啮合检测的归零
   - 操作前需进行绳索张力标定

**当前限制：**

固件实现仅完成 25%。STM32F103ZET6 控制板已完成设计并提供 PCB 原理图，但固件缺少：
- 控制回路初始化（TIM6 20kHz 中断未调用）
- 电机驱动 PWM 输出
- 从 GMR 传感器读取编码器（2400 计数/转）
- 串口协议解析器
- PID 控制回路
- 安全功能（限流、堵转检测、看门狗）

**与仿真的集成：**

windows_sim 环境采用简化模型（IdealOpenRSTModel），将夹爪视为 pitch/yaw/grasp 而非 pitch/finger_left/finger_right。此语义不匹配意味着仿真验证不能直接迁移至硬件控制。绳索动力学（拉伸、摩擦、迟滞）被刻意从仿真中省略。

**硬件在环测试（已规划）：**

固件完成后，测试流程应包含：
1. 通过串口协议命令各独立关节
2. 验证绳索张力响应与位置精度
3. 表征绳索拉伸补偿特性
4. 验证安全限制（电流、位置、速度）
5. 测量从串口命令到运动完成的端到端延迟

固件烧录、标定流程和实时控制的使用说明需待固件完成后确认。

## 7. 风险与限制

| 风险 | 影响 | 证据 | 缓解措施 |
|------|--------|----------|------------|
| 仿真与硬件模型间的语义不匹配 | 高 | 仿真采用 pitch/yaw/grasp（对称）但硬件 URDF 定义 pitch/finger_left/finger_right（独立）。windows_sim 的 IdealOpenRSTModel 与 openrst.urdf 结构不兼容 | 选择统一控制模型：修改仿真以使用独立钳口，或约束硬件采用对称抓取。相应更新 openrst_model.py 或 openrst.urdf |
| 仿真未建模绳索动力学 | 高 | IdealOpenRSTModel 刻意省略绳索拉伸、摩擦、迟滞。实际硬件可能表现出显著差异，需大量调优 | 规划硬件表征阶段：测量绳索拉伸与张力关系，识别摩擦系数，在固件 PID 调优中实现补偿 |
| 固件实现仅完成 25% | 关键 | 仅板级启动，无控制回路、无 PID、无串口协议、无安全功能（据分析数据） | 分配 2-3 周嵌入式开发。优先级：控制回路初始化、电机控制、串口协议、安全功能 |
| 无物理装配证据 | 高 | Dummy 臂法兰安装状态未知，绳索走线未记录，机械可行性未验证 | 创建机械集成检查清单：验证法兰尺寸、3D 打印接口模块、记录绳索走线约束、测试机械干涉 |
| 与 Dummy 臂的控制架构不匹配 | 中 | 原始 OpenRST 采用昂贵数据采集板 + ROS1。项目 STM32 独立方案为未经测试的分化方案。独立串口相比 CAN 总线集成增加延迟 | 通过原型测试验证 STM32 独立方案。若串口延迟超出预算，考虑迁移至 CAN 总线以统一控制 |
| 通过独立串口集成增加复杂性 | 中 | 设计为与 Dummy 臂分离的独立串口而非 CAN 总线集成。增加通信路径、提高延迟、引入独立故障模式 | 采用串口方案基准测试端到端延迟。若开销 >20ms，考虑 CAN 总线迁移以统一 Dummy 臂控制架构 |
