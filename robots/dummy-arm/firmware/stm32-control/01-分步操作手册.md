# 01 - 分步操作手册（硬件损坏防护操作规程）

---

## 区域用途

本手册用于指导技术人员完成 STM32 控制器固件的第一阶段（MCU 最小系统验证）操作流程，涵盖硬件连接、驱动安装、CubeMX 工程配置、Keil 编译、固件烧录及串口通信测试。本阶段操作严格限定于无电机、无驱动板、无 12V 高压供电的安全配置，最大限度降低硬件损坏风险。

### 阶段 1：MCU 最小系统验证（预计耗时 30 分钟）

#### 阶段目标

执行下述步骤后，可实现以下功能验证：
- 硬件连接（DAP 下载器 + CH340 串口模块）
- 设备驱动程序安装
- CubeMX 工程配置（TIM6 + ADC）
- Keil 工程编译
- 固件烧录
- 串口通信测试

#### 硬件损坏风险控制

本阶段通过以下约束条件保证硬件安全：
- 不连接电机
- 不连接驱动板
- 不连接 12V 外部电源
- 仅使用 USB 端口供电（5V）
- 仅连接信号线

### 步骤一：硬件连接（前置条件）

若尚未完成硬件接线操作，请先执行 `00-安全第一.md` 中的接线操作规程。

#### 连接状态检查清单

```
□ DAP 已连接野火板 SWD 接口（SWDIO, SWCLK, GND）
□ CH340 已连接野火板串口（TX→PA10, RX→PA9, GND）
□ 野火板 USB 已供电（电源指示灯点亮）
□ DAP 和 CH340 均已通过 USB 连接至开发主机
□ 设备管理器中可识别 CMSIS-DAP 设备与 COM 端口
```

### 步骤二：软件环境安装（预计耗时 10 分钟）

#### 必需软件清单

##### 1. STM32CubeMX（必需）
- 下载地址：https://www.st.com/zh/development-tools/stm32cubemx.html
- 版本要求：6.x 或更高
- 安装方式：执行安装程序，使用默认路径即可

##### 2. Keil MDK-ARM（必需）
- 下载地址：https://www.keil.com/download/product/
- 版本要求：5.x 或更高
- STM32F1xx 器件支持包安装流程：
  1. 完成 Keil 主程序安装
  2. 启动 Keil
  3. 菜单入口：Pack Installer
  4. 搜索关键词：STM32F1
  5. 安装组件：Keil::STM32F1xx_DFP

##### 3. 串口终端工具（任选其一）
- SSCOM
- Tera Term：https://ttssh2.osdn.jp/
- MobaXterm：https://mobaxterm.mobatek.net/

##### 4. CH340 驱动程序（必需）
- 驱动归档位置：`docs/WHEELTEC 直流电机附送资料/.../CH340驱动.rar`
- 安装方式：解压归档后执行安装程序

### 步骤三：CubeMX 工程配置（预计耗时 10 分钟）

**注意：** 本步骤为必需操作项。若缺少 TIM6 与 ADC 配置，将导致编译错误或固件烧录后功能异常。

#### 配置原理说明

```
原始代码生成阶段未包含 TIM6 与 ADC 配置，
若不执行下述手动配置，将导致编译报错或功能失效。
```

#### 1. 打开工程文件

```
双击文件：rst-control-fw/rst-control-fw.ioc
```

等待 CubeMX 工程加载完成（加载耗时约 1-2 分钟）。

---

#### 2. TIM6 定时器配置（20kHz 控制循环时基）

在左侧导航栏定位 **Timers** → 选择 **TIM6**。

1. 勾选 `Activated` 选项以启用定时器。

2. 进入 TIM6 配置界面。

3. **Parameter Settings** 选项卡参数配置：
   ```
   Prescaler (16 bits value):    35
   Counter Period (AutoReload):  99
   auto-reload preload:          Disable
   ```

4. **NVIC Settings** 选项卡参数配置：
   ```
   勾选：TIM6 global interrupt
   Priority: 0 (最高优先级)
   ```

#### 配置参数计算验证

```
时基计算验证：72MHz / (35+1) / (99+1) = 20,000 Hz = 20kHz
```

---

#### 3. ADC1 与 DMA 配置（电流采样通道）

在左侧导航栏定位 **Analog** → 选择 **ADC1**。

1. **Mode** 设置：
   ```
   勾选：IN3
   勾选：IN4
   勾选：IN5
   ```

2. **Configuration** 选项卡 → **Parameter Settings** 配置：
   ```
   Clock Prescaler:          PCLK2 divided by 6
   Resolution:               12 bits (15 ADC Clock cycles)
   Data Alignment:           Right alignment
   Scan Conversion Mode:     Enable
   Continuous Conversion:    Enable
   Discontinuous Conv Mode:  Disable
   DMA Continuous Requests:  Enable
   Number of Conversion:     3
   ```

3. **Rank 配置**（同一页面下方区域）：
   ```
   Rank 1:
     Channel: Channel 4
     Sampling Time: 55.5 Cycles
   
   Rank 2:
     Channel: Channel 5
     Sampling Time: 55.5 Cycles
   
   Rank 3:
     Channel: Channel 3
     Sampling Time: 55.5 Cycles
   ```

4. **DMA Settings** 选项卡 → 点击 **Add** 按钮：
   ```
   DMA Request:     ADC1
   Stream:          DMA1 Channel 1
   Direction:       Peripheral To Memory
   Priority:        Medium
   Mode:            Circular
   
   Increment Address:
     Peripheral:    不勾选
     Memory:        勾选
   
   Data Width:
     Peripheral:    Half Word
     Memory:        Half Word
   ```

---

#### 4. 其他配置项核验（请勿修改）

核验以下配置项是否已正确设置（代码生成阶段应已配置完成）：

**Timers 组：**
```
TIM1: PWM Generation CH1
TIM2: Encoder Mode
TIM3: Encoder Mode
TIM4: Encoder Mode
TIM8: PWM Generation CH1, CH2
```

**Connectivity 组：**
```
USART1: Asynchronous, 115200 bps
CAN: Master mode
```

**注意：** 若上述配置项存在偏差，请勿直接修改。应记录偏差并进行技术复核。

##### 命令：`info`
**预期输出：**
```
  --- 系统信息 ---
  MCU:       STM32F103ZET6 @ 72MHz
  UART:      USART1 @ 115200 bps
  CAN ID:    0 (1Mbps)   ← 注意：ID 恒为 0，"1Mbps" 标注错误，实测值为 562.5kbps
  Loop Cnt:  0           ← 注意：恒为 0，属预期状态，见下述说明
  Motors:    3 (0=Pitch 1=UpperJaw 2=LowerJaw)
  
  --- 电机状态 ---
  [0] Pitch : mode=0 st=NOCAL ang=0.00 mA=0 pwm=0
  [1] UpJaw : mode=0 st=NOCAL ang=0.00 mA=0 pwm=0
  [2] LoJaw : mode=0 st=NOCAL ang=0.00 mA=0 pwm=0
```

**注意：** 原验收标准已作废（2026-08-09 代码实测复核）。

原文档描述"若 `Loop Cnt` 字段数值递增，则表明 20kHz 控制循环正常运行"。该判据在当前代码版本下**恒不成立**，其失效原因包含两层：

1. `g_rst.loop_count` 变量在整个工程范围内仅在 `control_loop.c:41` 处被赋值为 0，**未存在任何自增操作**。即使控制循环正常执行，该字段值亦不会发生变化。
2. 20kHz 定时器中断本身未被启动。`MX_TIM6_Init()` 函数从未被调用（`main.c:95-104` 初始化函数列表中未包含该调用），因此 `htim6.State` 状态停留在 `HAL_TIM_STATE_RESET`；而 `control_loop.c:79` 的 `HAL_TIM_Base_Start_IT(&htim6)` 调用首项判断即为 `if (htim->State != HAL_TIM_STATE_READY) return HAL_ERROR;`，函数直接返回错误状态。由于返回值未执行检查，串口终端仍输出 "Control loop started at 20kHz" 信息——**该输出信息与实际运行状态不符**。

**当前阶段有效验收标准**（已通过实测验证的功能项）：
- 串口终端正确打印启动横幅
- `help` 命令输出 11 条可用命令列表
- `info` 命令返回正常（其中 `Loop Cnt` 恒为 0、`mA` 恒为 0、`ang` 恒为 4915.20 均属预期值，非故障状态）
- 输入未定义命令时返回 "未知命令" 提示

满足上述四项条件即表明**串口控制台链路功能正常**，可进入下一工作阶段。**注意：** `Loop Cnt` 字段不可作为任何功能判据使用。

详细的偏差清单参见 `固件真实状态.md`。

#### 6. 串口通信异常处置

##### 问题 1：完全无输出

```
原因分析：波特率参数配置不匹配。
处置方法：确认串口终端工具波特率参数为 115200。
```

##### 问题 3：有输出但 Loop Cnt 字段数值不递增
```
该现象属当前代码版本的既定行为，非故障状态，无需进行故障排查。

根本原因（两层，均需修改代码后方可解决）：
  1. loop_count 变量未存在任何自增操作（control_loop.c 中仅存在一处赋 0 操作）
  2. MX_TIM6_Init() 函数从未被调用，TIM6 中断未实际启动

**严禁**按原文档描述执行"重新生成 CubeMX 代码"操作——
重新生成代码将覆盖 gpio.c 文件中的手写配置，反而引入新的故障（详见 `固件真实状态.md` GPIO 章节）。

若需恢复该功能，应按 `固件真实状态.md` 中"修复顺序"章节执行。
```

#### 不可由阶段 1 直接推断的事项（重要说明）

阶段 1 验证通过仅证明 **MCU 最小系统工作正常、串口通信链路畅通、控制台交互功能有效**。**不**可据此推断以下功能项已实现：

```
✗ 20kHz 控制循环处于运行状态   —— 经实测该循环未启动（参见 固件真实状态.md 问题 A）
✗ 编码器计数功能正常           —— 编码器外设未执行 Start 操作
✗ 电流采样数据有效           —— ADC 仅执行单轮转换后即停止
✗ PWM / LED / 方向引脚功能可用 —— GPIOB/GPIOE 端口时钟未使能
```

阶段 1 验证通过后**严禁**直接进入阶段 2 或阶段 3 的电机连接操作。应首先按 `固件真实状态.md` 中"修复路线"章节完成 A–E 五项阻塞性问题修复，否则即使接入电机亦无法实现任何闭环控制行为。

### 后续工作路径

原文档描述的"阶段 2 编码器测试"当前无法执行：编码器外设未启动，
`enc` 命令读取的 CNT 计数值不随电机轴转动发生变化（参见 `固件真实状态.md` 问题 C）。

正确的后续工作路径应为按 `固件真实状态.md` 中"修复路线"章节依次处理下述问题：

```
A. main.c 补充 MX_TIM6_Init() 调用          —— 使 20kHz 中断正常启动
B. gpio.c 恢复被 CubeMX 覆盖的 GPIO 配置 —— 恢复 LED/方向引脚/按键/拨码开关功能
C. 补充 HAL_TIM_Encoder_Start() 调用        —— 启动编码器计数功能
D. 补充 HAL_TIM_PWM_Start() 调用            —— 使能 PWM 输出通道
E. ADC 修改为连续模式 + 修正 Rank3 通道配置    —— 使三路电流采样数据有效
```

**在 A–E 五项问题修复完成前，严禁接入 12V 电源与电机：** 当前固件版本既未实现电流限幅功能，
亦未配置堵转检测与指令超时保护机制，一旦 PWM 输出通道使能将不存在任何软件层面的保护措施。

固件修复工作应严格按既定步骤逐步推进，**不得跳过任何修复项直接进入电机测试阶段**。

## 风险与局限

- 当前固件版本 `Loop Cnt` 字段恒为 0，该字段不可作为控制循环运行状态的判据
- 阶段 1 验证通过仅表明 MCU 最小系统与串口通信链路正常，**不可**据此推断电机、编码器等外围功能可用
- CubeMX 代码生成操作将覆盖 `gpio.c` 中的手写引脚配置，操作前必须进行文件备份
- 完成阶段 1 验证后，严禁直接接入电机与 12V 电源，应首先完成固件阻塞性问题修复
