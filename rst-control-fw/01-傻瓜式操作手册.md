## Step 3：CubeMX 配置（10分钟）⚠️ 重要

### 为什么必须配置？
```
原因：DeepSeek 没有配置 TIM6 和 ADC
结果：编译会报错，或者烧录后不工作
```

### 操作步骤：

#### 1. 打开项目
```
双击文件：rst-control-fw/rst-control-fw.ioc
```

等待 CubeMX 加载（可能需要 1-2 分钟）

---

#### 2. 配置 TIM6（20kHz 控制循环）

**左侧找到 Timers → TIM6**

1. 勾选 `Activated`

2. 点击 TIM6 进入配置界面

3. **Parameter Settings** 选项卡：
   ```
   Prescaler (16 bits value):    35
   Counter Period (AutoReload):  99
   auto-reload preload:          Disable
   ```

4. **NVIC Settings** 选项卡：
   ```
   勾选：TIM6 global interrupt
   Priority: 0 (最高优先级)
   ```

**为什么这样配置？**
```
计算：72MHz / (35+1) / (99+1) = 20,000 Hz = 20kHz ✅
```

---

#### 3. 配置 ADC1 + DMA（电流采样）

**左侧找到 Analog → ADC1**

1. **Mode** 设置：
   ```
   勾选：IN3
   勾选：IN4
   勾选：IN5
   ```

2. **Configuration** 选项卡 → **Parameter Settings**：
   ```
   Clock Prescaler:          PCLK2 divided by 6
   Resolution:               12 bits (15 ADC Clock cycles)
   Data Alignment:           Right alignment
   Scan Conversion Mode:     Enable
   Continuous Conversion:    Enable
   Discontinuous Conv Mode:  Disable
   DMA Continuous Requests:  Enable
   Number of Conversion:     3
   ```

3. **Rank 配置**（在同一页面下方）：
   ```
   Rank 1:
     Channel: Channel 4
     Sampling Time: 55.5 Cycles
   
   Rank 2:
     Channel: Channel 5
     Sampling Time: 55.5 Cycles
   
   Rank 3:
     Channel: Channel 3
     Sampling Time: 55.5 Cycles
   ```

4. **DMA Settings** 选项卡 → 点击 **Add**：
   ```
   DMA Request:     ADC1
   Stream:          DMA1 Channel 1
   Direction:       Peripheral To Memory
   Priority:        Medium
   Mode:            Circular
   
   Increment Address:
     Peripheral:    □ 不勾选
     Memory:        ✅ 勾选
   
   Data Width:
     Peripheral:    Half Word
     Memory:        Half Word
   ```

---

#### 4. 检查其他配置（不要修改）

确认以下配置已存在（DeepSeek 应该配置过了）：

**Timers:**
```
✅ TIM1: PWM Generation CH1
✅ TIM2: Encoder Mode
✅ TIM3: Encoder Mode
✅ TIM4: Encoder Mode
✅ TIM8: PWM Generation CH1, CH2
```

**Connectivity:**
```
✅ USART1: Asynchronous, 115200 bps
✅ CAN: Master mode
```

**如果有任何不对，不要修改！告诉我！**

  CAN ID:    0 (1Mbps)   ← 注意：ID 恒为 0，"1Mbps" 是错的，实测 562.5kbps

  [2] LoJaw : mode=0 st=NOCAL ang=0.00 mA=0 pwm=0

> ⚠️ **本节原验收标准已作废（2026-08-09 代码核对）**
>
> 原文写"如果 `Loop Cnt` 增加了，说明 20kHz 控制循环正常运行"。这条判据在当前代码下**永远无法满足**，而且它不成立的原因有两层：
>
> 1. `g_rst.loop_count` 在整个工程里只被 `control_loop.c:41` 赋值为 0，**没有任何地方对它做过 `++`**。即使控制循环全速运行，这个数也不会变。
> 2. 20kHz 中断本身也没有启动。`MX_TIM6_Init()` 从未被调用（`main.c:95-104` 的初始化列表里没有它），所以 `htim6.State` 停在 `HAL_TIM_STATE_RESET`；而 `control_loop.c:79` 的 `HAL_TIM_Base_Start_IT(&htim6)` 第一步就是 `if (htim->State != HAL_TIM_STATE_READY) return HAL_ERROR;`，直接返回错误。返回值没人检查，所以串口照样打印 "Control loop started at 20kHz"——**那行输出是假的**。
>
> **当前阶段真正可用的验收标准**（这些是已验证能工作的）：
> - 串口能打印启动横幅
> - `help` 列出 11 条命令
> - `info` 能正常返回（其中 `Loop Cnt` 恒为 0、`mA` 恒为 0、`ang` 恒为 4915.20 都是预期值，不是故障）
> - 输入乱命令回 "未知命令"
>
> 看到上面四条就说明**串口控制台链路正常**，可以进入下一步。不要用 `Loop Cnt` 判断任何事情。
>
> 详细的偏差清单见 `固件真实状态.md`。

## 🎯 下一步：不是接电机，而是修固件

原先这里写的"阶段 2 编码器测试"现在做不了：编码器外设从未启动，
`enc` 命令读到的 CNT 不会随电机转动变化（见 `../固件真实状态.md` 问题 C）。

正确的下一步是按 `../固件真实状态.md` 的"修复路线"依次处理：

```
A. main.c 补 MX_TIM6_Init()          —— 让 20kHz 中断真正起来
B. gpio.c 的 GPIO 配置被 CubeMX 覆盖 —— 恢复 LED/方向脚/按键/拨码
C. 补 HAL_TIM_Encoder_Start()        —— 让编码器开始计数
D. 补 HAL_TIM_PWM_Start()            —— 让 PWM 真正输出
E. ADC 改连续模式 + 修 Rank3 通道    —— 让三路电流有效
```

**在 A–E 修完之前不要接 12V 电源和电机**：此时既没有电流限幅，
也没有堵转保护和指令超时，一旦 PWM 能输出就没有任何软件层面的兜底。

**不要着急接电机，一步步来。** 🚀
