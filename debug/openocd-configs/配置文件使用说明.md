# OpenOCD 调试配置文件

这个目录包含了用于 OpenOCD 调试和烧录的配置文件。

---

## 📁 配置文件列表

| 文件 | 调试器 | 目标芯片 | 适用项目 |
|------|--------|----------|----------|
| `stlink-f103.cfg` | ST-Link V2/V2.1/V3 | STM32F103ZE | rst-control-fw |
| `cmsis-dap-f103.cfg` | CMSIS-DAP / DAPLink | STM32F103ZE | rst-control-fw |
| `dap-f103.cfg` | 野火 DAP 小智款（CMSIS-DAP v1 HID） | STM32F103ZE | rst-control-fw |
| `wch-link-f103.cfg` | WCH-Link / WCH-LinkE | STM32F103ZE | rst-control-fw |
| `stlink-f405.cfg` | ST-Link V2/V2.1/V3 | STM32F405RG | dummy-ref-core-fw |

## 🚀 快速开始

### 1. 测试连接

```bash
# 进入项目目录
cd /e/Robotic-Arm

# 使用对应的配置文件测试连接
openocd -f openocd-configs/stlink-f103.cfg
```

如果连接成功，你会看到：
```
Info : STLINK V2J37S7 (API v2) VID:PID 0483:3748
Info : Target voltage: 3.245V
Info : stm32f1x.cpu: hardware has 6 breakpoints, 4 watchpoints
```

按 `Ctrl+C` 退出。

### 自动化连接测试

使用 test-connection.sh 脚本自动测试所有配置：

```bash
cd /e/Robotic-Arm/debug/openocd-configs
./test-connection.sh
```

脚本将按顺序测试所有配置，每个配置超时 3 秒，自动识别可用调试器并将工作配置保存到 `/tmp/openocd_working_config.txt`。

### 2. 烧录固件

#### 方法 A: 使用 OpenOCD 命令行

```bash
# 烧录 rst-control-fw (ST-Link)
openocd -f openocd-configs/stlink-f103.cfg \
  -c init \
  -c "reset halt" \
  -c "flash write_image erase rst-control-fw/control/build/control.elf" \
  -c "verify_image rst-control-fw/control/build/control.elf" \
  -c "reset run" \
  -c exit
```

#### 方法 B: 使用 program 命令（推荐）

```bash
openocd -f <config> -c "program firmware.elf verify reset exit"
```

#### 方法 C: 使用自定义 flash_program 过程

```bash
openocd -f <config> -c init -c "flash_program firmware.elf" -c exit
```

#### 方法 D: 使用 VSCode 任务

在 VSCode 中按 `Ctrl+Shift+P`，选择 `Tasks: Run Task`，然后选择对应的烧录任务。

### 3. 启动 GDB 调试

#### 终端 1: 启动 OpenOCD 服务器

```bash
openocd -f openocd-configs/stlink-f103.cfg
```

保持这个终端运行，OpenOCD 会监听 GDB 连接（默认端口 3333）。

#### 终端 2: 启动 GDB

```bash
# 进入固件目录
cd rst-control-fw/control/build

# 启动 GDB 并连接到 OpenOCD
arm-none-eabi-gdb control.elf \
  -ex "target extended-remote localhost:3333" \
  -ex "monitor reset halt" \
  -ex "load" \
  -ex "monitor reset init"
```

#### 方法 E: 使用 VSCode 调试器（推荐）

1. 在 VSCode 中打开项目
2. 按 `F5` 或点击调试面板的 "Start Debugging"
3. 选择对应的调试配置（已在 `.vscode/launch.json` 中配置）

## 🔧 配置文件说明

### stlink-f103.cfg

适用于 ST-Link 调试器 + STM32F103ZE。

**特点：**
- 使用 HLA (High Level Adapter) 接口
- SWD 速度：1.8 MHz
- 包含烧录和验证辅助函数（halt_target、reset_target、flash_program）
- 已配置 GDB 附加/分离事件处理器

**修改选项：**
```tcl
# 调整 SWD 速度 (如果连接不稳定，可以降低)
adapter speed 1000  # 降低到 1 MHz

# 如果需要使用 JTAG 而不是 SWD
transport select hla_jtag
```

### cmsis-dap-f103.cfg

适用于 CMSIS-DAP / DAPLink 调试器 + STM32F103ZE。

**特点：**
- 标准 CMSIS-DAP 协议
- 兼容多种开源调试器（DAPLink、ULINK2、LPC-Link2 等）
- SWD 速度：1 MHz
- 包含与 stlink-f103.cfg 相同的辅助 TCL 过程

**指定设备 VID/PID：**
```tcl
# 取消注释并填入你的设备 ID
cmsis_dap vid_pid 0x0d28 0x0204

# 常见 CMSIS-DAP 设备：
# DAPLink:      0x0d28:0x0204
# Keil ULINK2:  0xc251:0x2750
# LPC-Link2:    0x1fc9:0x0090
```

**指定设备序列号：**
```tcl
# 如果有多个 CMSIS-DAP 设备连接
cmsis_dap serial 123456789
```

### dap-f103.cfg

适用于野火 DAP 小智款（CMSIS-DAP v1 HID 传输）+ STM32F103ZET6。**此配置为特定硬件验证版本。**

**特点：**
- 关键修复：指定 `cmsis-dap backend hid` 以使用 CMSIS-DAP v1 HID 传输
- 解决标准 cmsis-dap-f103.cfg 在野火 DAP 小智款上的 `hid_write failed` 错误
- SWD 速度：1 MHz
- 已使用序列号 6D656D6F7279 硬件验证

**适用场景：**
- 野火 DAP 小智款调试器
- 其他使用 HID 传输的 CMSIS-DAP v1 设备
- 遇到 `hid_write failed` 错误时的替代方案

### wch-link-f103.cfg

适用于 WCH-Link / WCH-LinkE 调试器 + STM32F103ZE。

**特点：**
- 国产调试器，性价比高
- 使用 CMSIS-DAP 协议，指定 WCH 专用 VID/PID
- VID/PID：0x0416:0x5021
- SWD 速度：1 MHz

**注意事项：**
1. 需要安装 WCH 官方驱动
2. OpenOCD 可能需要较新版本才能完全支持
3. 如果 OpenOCD 无法识别，可以尝试使用 WCH-LinkUtility
4. 部分 WCH-Link 设备仅支持 RISC-V，请确认型号支持 ARM 架构

**检查设备 VID/PID：**
```bash
# 在 Windows PowerShell 中
Get-PnpDevice | Where-Object {$_.FriendlyName -like "*WCH*"}
```

### stlink-f405.cfg

适用于 ST-Link 调试器 + STM32F405RG（dummy-ref-core-fw 项目）。

**特点：**
- 配置结构与 `stlink-f103.cfg` 一致
- 使用 `stm32f4x.cfg` 目标配置而非 stm32f1x.cfg
- 168MHz CPU 时钟，适配 SWO/ITM 跟踪时序参数
- 闪存基地址：0x08000000（与 F1 系列相同）

## 📝 自定义配置

### 修改 SWD 速度

```tcl
# 在配置文件中修改
adapter speed 1000  # 单位: kHz
```

常见速度设置：
- **500 kHz**：最稳定，用于长杜邦线或电磁干扰环境
- **1000 kHz**：标准速度，平衡稳定性与传输速率
- **1800 kHz**：快速，用于短距离高质量连接
- **4000 kHz**：最快（需要调试器和芯片同时支持）

### 添加自定义烧录函数

在配置文件末尾添加：

```tcl
proc my_flash {bin_file address} {
    reset halt
    flash write_image erase $bin_file $address bin
    verify_image $bin_file $address bin
    reset run
}
```

使用方法：
```bash
openocd -f openocd-configs/stlink-f103.cfg \
  -c init \
  -c "my_flash firmware.bin 0x08000000" \
  -c exit
```

### 启用 SWO (Serial Wire Output) 跟踪

在配置文件中添加：

```tcl
# 启用 ITM (Instrumentation Trace Macrocell)
$_TARGETNAME configure -event reset-init {
    # 设置 TPIU 时钟
    mmw 0xE0042004 0x00000027 0
    
    # 设置 ITM 通道
    mww 0xE0000E80 0x00000001
    mww 0xE0000E00 0x00000001
    mww 0xE0000FB0 0xC5ACCE55
}

# 启动 SWO 跟踪
tpiu config internal swo.log uart off 72000000
```

**注意：** F405 目标（168MHz）需将最后一行的时钟频率改为 `168000000`。

## 🐛 故障排除

### 问题 1: `Error: unable to find a matching CMSIS-DAP device`

**原因：** OpenOCD 找不到指定的 CMSIS-DAP 设备。

**解决方法：**
1. 检查 USB 物理连接是否牢固
2. 确认设备管理器中正确识别了调试器
3. 在配置中指定正确的 VID/PID：
   ```tcl
   cmsis_dap vid_pid 0x0416 0x5021
   ```
4. 尝试更换不同的 USB 端口（优先使用主板直接 USB 口）
5. 对于野火 DAP 小智款等 CMSIS-DAP v1 设备，使用 dap-f103.cfg 替代 cmsis-dap-f103.cfg

### 问题 2: `Error: could not get configuration descriptor`

**原因：** USB 驱动程序未正确安装或配置。

**解决方法：**
1. 安装调试器厂商提供的官方驱动程序
2. 对于 WCH-Link，务必安装 WCH 官方驱动
3. 对于 CMSIS-DAP 设备，使用 Zadig 工具安装 WinUSB 驱动
4. 在设备管理器中检查设备状态，确认无黄色感叹号

### 问题 3: `Error: init mode failed`

**原因：** 无法通过 SWD 接口连接到目标芯片。

**解决方法：**
1. 检查 SWD 连接线（SWDIO、SWCLK、GND、VCC）顺序和接触
2. 确认目标开发板已正常上电（测量 VCC 电压）
3. 降低 SWD 通信速度：
   ```tcl
   adapter speed 500
   ```
4. 检查目标板 BOOT0/BOOT1 引脚设置是否正确
5. 尝试按住复位键后连接，再松开复位键
6. 确认目标芯片未被读保护（RDP）锁定

### 问题 4: `Error: Target not halted`

**原因：** 目标芯片持续运行，无法进入调试暂停状态。

**解决方法：**
1. 在 OpenOCD 命令中显式使用 `reset halt` 停止芯片
2. 检查是否启用了芯片读保护（RDP 等级 1/2），读保护会阻止调试连接
3. 尝试断电重启目标板后立即发起连接
4. 检查芯片是否进入低功耗模式（STOP/STANDBY），阻止了调试接口

### 问题 5: WCH-Link 无法在 OpenOCD 中使用

**解决方法：**
1. 使用 WCH 官方工具 WCH-LinkUtility 进行烧录和调试
2. 或使用 WCH 提供的修改版 OpenOCD（支持 WCH 专用协议扩展）
3. 确认 WCH-Link 固件版本是否支持 ARM 芯片架构（部分型号仅支持 RISC-V）
4. 尝试使用 `cmsis-dap backend hid` 选项（参考 dap-f103.cfg 的实现）

## 💡 使用技巧

### 快速烧录（不启动调试）

```bash
# 创建别名（在 ~/.bashrc 或 ~/.bash_profile 中）
alias flash-f103='openocd -f openocd-configs/stlink-f103.cfg -c "program rst-control-fw/control/build/control.elf verify reset exit"'

# 使用
flash-f103
```

### 读取芯片信息

```bash
openocd -f openocd-configs/stlink-f103.cfg \
  -c init \
  -c "flash info 0" \
  -c exit
```

### 擦除整个 Flash

```bash
openocd -f openocd-configs/stlink-f103.cfg \
  -c init \
  -c "reset halt" \
  -c "stm32f1x mass_erase 0" \
  -c "reset run" \
  -c exit
```

**警告：** 批量擦除操作具有破坏性，可能擦除芯片上的引导加载程序。执行前请确认。

### 读取 Flash 内容到文件

```bash
openocd -f openocd-configs/stlink-f103.cfg \
  -c init \
  -c "reset halt" \
  -c "dump_image firmware_backup.bin 0x08000000 0x10000" \
  -c exit
```

### 直接闪存操作序列（手动烧录）

```bash
openocd -f <config> \
  -c init \
  -c "reset halt" \
  -c "flash write_image erase firmware.elf" \
  -c "verify_image firmware.elf" \
  -c "reset run" \
  -c exit
```
