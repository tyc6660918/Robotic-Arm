# AI 自动调试能力分析

## 1. 区域用途

本区域为 STM32 固件开发提供三层 AI 辅助调试能力：(1) 通过 `stm32-autonomous-debug` 技能实现完全自主的闭环调试，该技能可在无需人工干预的情况下检测、诊断并自动修复常见固件故障；(2) 半自主远程调试，由 Claude 分析 GDB 诊断输出并提出修复建议；(3) 通过 VSCode + OpenOCD + GDB 进行的手动交互式调试，附带全面的配置和指南。该系统基于历史 E:\ClaudetoST 故障案例的实证构建，支持 STM32F103ZE 和 STM32F405RG 目标，配合 ST-Link、CMSIS-DAP 和 WCH-Link 调试器使用。

## 6. 使用说明

### 第 1 层：完全自主调试

调用 `stm32-autonomous-debug` 技能以触发 7 阶段闭环工作流：

1. **项目识别**：检测 CMake/Keil/Makefile 项目并提取构建命令
2. **环境检查**：验证 arm-none-eabi-gcc、OpenOCD、带 pyserial 的 Python 是否已安装
3. **编译**：运行检测到的构建命令，将输出捕获到 compile.log
4. **编译后验证**：检查固件大小（1KB-512KB）、向量表大小（F103ZE 为 0x130）、关键初始化函数链接（TIM6_Init、GPIO_Init、PWM_Start、ADC_Start）
5. **烧录**：尝试标准烧录（10MHz），失败则回退到低速（500kHz），必要时批量擦除。保存工作配置。
6. **串口监控**：枚举所有 COM 端口，尝试 115200/9600/57600 波特率，捕获 5 秒输出，分析 clock/loop/error 关键字
7. **自动修复**：根据故障类型检测应用修复：
   - TIM6_NOT_CALLED：在 main.c 的 while 循环前插入 `MX_TIM6_Init();`
   - PWM_NOT_STARTED：插入 `HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);` 调用
   - GPIO_NOT_CONFIGURED：在 CubeMX 区域外创建隔离的 GPIO 初始化函数
   - VECTOR_TABLE_INCOMPLETE：向启动文件添加缺失的 17 个向量
8. **迭代**：返回编译步骤，最多 5 次迭代

日志保存到项目根目录：compile.log、flash.log、serial_COMx_BAUD.log、environment.log、project_state.env

### 第 2 层：半自主（Claude 远程调试）

收集 GDB 诊断数据并发送给 Claude 进行分析：

```bash
# 启动 OpenOCD
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg

# 在另一个终端中，运行 GDB 诊断脚本
arm-none-eabi-gdb firmware.elf
source gdb-diagnostic.txt
```

gdb-diagnostic.txt 收集：程序状态、回溯、寄存器、局部变量、GPIO 状态（0x40010808 处的 IDR/ODR）、USART 寄存器（0x40013800 处的 7 个字）、DMA 通道（ISR + CCR/CNDTR/CPAR/CMAR）、RCC 时钟。将输出与观察到的行为描述一起发送给 Claude。

Claude人工智能远程调试指南.md 中记录的示例场景：
- 程序未运行：检查 PC、回溯、复位处理程序执行
- USART 无输出：检查 GPIOA CRH 的 PA9 配置（应为 0xB 表示复用推挽，而非 0x4）、USART_SR/DR
- DMA 传输失败：检查 DMA_ISR 标志、CCR 启用位、CNDTR 剩余计数、CPAR/CMAR 地址
- 程序失控：检查是否存在 HardFault（CFSR 在 0xE000ED28、HFSR 在 0xE000ED2C、BFAR 在 0xE000ED34）

## 7. 风险与限制

| 风险 | 影响 | 证据 | 缓解措施 |
|------|--------|----------|------------|
| 仓库中缺少 rst-control-fw | 高 | 文档和 VSCode 配置中广泛引用但在 robots/ 结构中未找到 | 定位备份或将所有引用更新为 robots/Dummy-Arm/firmware/ 中的 stm32-control |
| 自主脚本包含硬编码的绝对路径 | 高 | C:/Users/TYC、C:/Keil_v5 不适用于其他用户 | 替换为环境变量或自动检测 |
| 自动修复在没有备份的情况下修改源文件 | 高 | 如果修复不正确，则无回滚机制 | 在应用修复前添加备份创建 |
| 批量擦除闪存操作具有破坏性 | 中 | 如果存在引导加载程序可能会被擦除 | 在批量擦除前添加引导加载程序存在检查 |
| 串口监控 5 秒超时可能会错过缓慢启动的固件 | 中 | 某些固件初始化和发送第一个输出可能需要超过 5 秒 | 使超时可配置或添加重试逻辑 |
| 编译后检查假设 HAL 库命名约定 | 中 | 不适用于裸机或非 HAL 项目 | 添加项目类型检测并调整检查 |
| 最多 5 次迭代可能不足 | 中 | 复杂的多问题固件可能需要更多轮次 | 使迭代限制可配置 |
| 仅支持 F1 系列 | 中 | 自主脚本不支持 dummy-ref-core-fw 中使用的 F4/F7/H7 | 作为下一个优先级扩展到 F4 系列 |
| 串口监控的 Python 依赖 | 低 | 可能并非在所有系统上都可用 | 回退到带说明的手动串口终端 |
| WCH-Link 兼容性问题 | 低 | 某些 WCH-Link 设备仅支持 RISC-V | 记录兼容的 WCH-Link 型号 |
| 无 FreeRTOS 任务分析 | 低 | 无法检查线程状态、堆栈使用率、调度器 | 向 Claude 模板添加 FreeRTOS 特定的 GDB 命令 |
| 无逻辑分析仪集成 | 低 | 硬件故障诊断需要外部工具 | 记录常见故障的预期逻辑分析仪捕获 |
