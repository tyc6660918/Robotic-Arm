## 一、硬件准备

### 调试器连接规程

#### 最小连接配置（4 线 SWD）

```
调试器引脚         STM32 开发板引脚
-------------    ------------------
SWDIO    <---->   SWDIO (PA13)
SWCLK    <---->   SWCLK (PA14)
GND      <---->   GND
VCC      <---->   3.3V（可选，用于供电检测）
```

#### 完整连接配置（含复位与串口）

```
调试器引脚         STM32 开发板引脚
-------------    ------------------
SWDIO    <---->   SWDIO (PA13)
SWCLK    <---->   SWCLK (PA14)
NRST     <---->   NRST（复位引脚）
GND      <---->   GND
VCC      <---->   3.3V
SWO      <---->   PB3（可选，用于 ITM 追踪输出）
TX       <---->   RX（可选，用于串口数据接收）
RX       <---->   TX（可选，用于串口数据发送）
```

### 硬件连接注意事项

1. **共地要求**：调试器与开发板的 GND 参考地必须可靠连接
2. **电压匹配要求**：确保调试器与开发板均采用 3.3 V 电压等级
3. **线缆长度限制**：SWD 信号线缆不宜超过 30 cm，过长将影响通信稳定性
4. **电磁环境要求**：安装与调试区域应远离高压、高频干扰源

## 三、快速启动规程

### 步骤 1：硬件系统连接

1. 使用 SWD 排线连接调试器与开发板，至少保证 SWDIO、SWCLK、GND 三线可靠连接
2. 为目标开发板接通电源
3. 将调试器插入上位机 USB 端口

### 步骤 2：通信链路测试

```bash
# 切换至项目根目录
cd /e/Robotic-Arm

# 执行连接测试脚本
bash debug/openocd-configs/test-connection.sh
```

当输出显示"成功连接"时，判定硬件配置正确。

### 步骤 3：Visual Studio Code 调试启动

1. 启动 Visual Studio Code，打开项目根目录
2. 在 `main.c` 的 `main()` 函数入口处设置断点（单击行号左侧空白区域）
3. 按 `F5` 快捷键或切换至"运行和调试"面板
4. 选择对应调试配置（例如 "rst-control-fw (CMSIS-DAP)"）
5. 系统将自动执行编译、烧录、启动流程，并在断点处暂停执行

## 四、调试方法

### 方法一：Visual Studio Code 图形界面调试（推荐）

**技术优势：**
- 可视化交互界面，操作直观
- 支持变量、寄存器、内存的实时查看
- 支持条件断点与数据监视点
- 集成编译与烧录流程

**操作规程：**

1. **断点设置**：在目标代码行号左侧单击，显示红色标记即为断点设置成功
2. **调试启动**：按 `F5` 快捷键，选择对应调试配置
3. **执行控制**：
   - `F5`——继续执行至下一断点或程序结束
   - `F10`——单步跳过（不进入被调函数内部）
   - `F11`——单步进入（进入被调函数内部）
   - `Shift+F11`——单步跳出（退出当前函数至调用点）
   - `Ctrl+Shift+F5`——重启调试会话
   - `Shift+F5`——终止调试会话

4. **变量查看**：
   - 将鼠标悬停于变量标识符上可查看当前值
   - 左侧"变量"面板可查看当前作用域内全部局部变量
   - 右键变量并选择"添加到监视"可实现持续跟踪

5. **外设寄存器查看**：
   - 左侧"外设"面板（需配置 SVD 文件支持）
   - 展开对应外设节点可查看 USART、GPIO、DMA 等外设的寄存器状态

### 方法二：命令行调试模式

**技术优势：**
- 执行灵活性高，支持任意 GDB 命令
- 适用于自动化脚本场景
- 支持远程调试部署

**终端 1：启动 OpenOCD 调试服务**

```bash
cd /e/Robotic-Arm
openocd -f debug/openocd-configs/stlink-f103.cfg
```

该终端需保持运行状态。

**终端 2：启动 GDB 客户端**

```bash
cd robots/Dummy-Arm/firmware/stm32-control/control
arm-none-eabi-gdb MDK-ARM/control/control.axf

# 在 GDB 交互提示符下执行
(gdb) target extended-remote localhost:3333
(gdb) monitor reset halt
(gdb) load                    # 烧录固件至目标 Flash
(gdb) break main              # 在 main 函数入口设置断点
(gdb) continue                # 继续执行至断点
(gdb) next                    # 单步执行
(gdb) print my_variable       # 打印变量当前值
(gdb) info registers          # 查看寄存器组状态
(gdb) backtrace               # 查看函数调用栈
```

### 方法三：固件烧录模式（不启动调试）

```bash
# 使用 OpenOCD 完成烧录
openocd -f debug/openocd-configs/stlink-f103.cfg \
  -c "program robots/Dummy-Arm/firmware/stm32-control/control/MDK-ARM/control/control.axf verify reset exit"
```

或使用 Visual Studio Code 任务系统：
- 按 `Ctrl+Shift+P` 快捷键
- 输入 "Tasks: Run Task"
- 选择前缀为 "Flash" 的对应烧录任务

## 五、高级调试功能

### 条件断点设置

在断点标记上右键单击，选择"编辑断点"，输入布尔条件表达式：

```c
// 示例：仅当 count 变量大于 10 时触发断点中断
count > 10
```

### 数据监视点（Watchpoint）

当被监视变量的值发生写操作时自动暂停执行：

```bash
# 在 GDB 交互提示符下执行
(gdb) watch my_variable
```

### 内存查看命令

```bash
# 以十六进制格式查看指定地址起 16 个字（4 字节）
(gdb) x/16xw 0x20000000

# 以 ASCII 字符串格式查看内存内容
(gdb) x/s 0x20000000
```

### 寄存器查看命令

```bash
# 查看全部核心寄存器状态
(gdb) info registers

# 查看特定寄存器值
(gdb) print $r0
(gdb) print $pc
(gdb) print $sp
```

### ITM 追踪输出功能

ITM（仪表追踪宏单元）支持固件直接向上位机发送调试信息。

**固件端实现（main.c 中添加）：**

```c
// ITM 单字符发送函数
void ITM_SendChar(char ch) {
    while (ITM->PORT[0].u32 == 0);  // 等待端口就绪
    ITM->PORT[0].u8 = (uint8_t)ch;  // 写入发送缓冲
}

// 调用示例
ITM_SendChar('H');
ITM_SendChar('i');
ITM_SendChar('\n');
```

**OpenOCD 端配置：**

在 OpenOCD 配置文件中启用 SWO 追踪通道，Visual Studio Code 将自动在"输出"面板中显示追踪数据。

### 硬件断点与软件断点机制

STM32F1 系列与 STM32F4 系列均内置 **6 个硬件断点**资源。

- **硬件断点**：适用于 Flash 中执行的代码，不修改原始指令代码
- **软件断点**：适用于 RAM 中执行的代码，需通过修改指令代码实现

GDB 将自动选择断点类型。当硬件断点资源耗尽时，将返回资源不足错误。

### Flash 下载加速配置

在 OpenOCD 配置文件中提升 SWD 时钟速率：

```tcl
adapter speed 4000  # 设置为 4 MHz（需硬件支持）
```

## 六、故障排查

### 故障一：OpenOCD 无法识别调试器

**故障特征：**
```
Error: unable to find a matching CMSIS-DAP device
```

**排查流程：**
1. 验证 USB 物理连接状态
2. 确认设备管理器中调试器已被正确识别
3. 更换不同 USB 端口重试
4. 检查 VID/PID 配置匹配性
5. 安装调试器官方驱动程序

### 故障二：OpenOCD 无法连接目标芯片

**故障特征：**
```
Error: init mode failed (unable to connect to the target)
```

**排查流程：**
1. 检查 SWD 连接（SWDIO、SWCLK、GND）接线顺序
2. 确认开发板已接通电源
3. 降低 SWD 通信速率（配置文件中设为 500 kHz）
4. 检查 BOOT0/BOOT1 引脚配置
5. 对开发板执行断电重启操作
6. 确认芯片未启用读保护（RDP 功能）

### 故障三：Visual Studio Code 调试器无法定位源代码

**故障特征：**
```
Cannot find source file ...
```

**排查流程：**
1. 确认编译时已启用 `-g` 选项以包含调试符号
2. 检查 `.elf` 或 `.axf` 文件路径配置正确性
3. 确认源代码文件未发生位置迁移

### 故障四：固件烧录完成后程序未运行

**可能原因：**
1. BOOT0 引脚配置错误（正常运行应接至 GND）
2. 看门狗复位触发（需在代码中执行喂狗操作）
3. 系统时钟配置错误
4. 硬件异常（HardFault 触发）

**诊断方法：**
```bash
# 建立连接后读取程序计数器
(gdb) monitor reset halt
(gdb) print $pc

# 若 PC 寄存器指向 HardFault_Handler，说明发生硬件异常
(gdb) backtrace  # 分析调用栈定位出错位置
```

### 故障五：单步调试时执行流跳变异常

**原因分析：**编译器优化导致源代码与机器码之间不存在一一对应关系。

**解决方法：**
在 CMakeLists.txt 配置中使用 `-O0` 选项禁用优化：

```cmake
set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -O0 -g3")
```

### 故障六：WCH-Link 调试器无法正常工作

**排查流程：**
1. 确认已安装 WCH 官方驱动程序
2. 检查 WCH-Link 固件版本是否支持 ARM 架构（部分型号仅支持 RISC-V）
3. 使用 WCH-LinkUtility 工具执行连接测试
4. 建议更换为 ST-Link 调试器（兼容性更优）

## 七、调试技巧与参考命令

### 技巧一：HardFault 根因分析

程序执行进入 HardFault 异常时，按以下流程诊断：

```bash
(gdb) monitor reset halt
(gdb) backtrace         # 查看函数调用栈
(gdb) info registers    # 查看寄存器组状态
(gdb) print $lr         # 查看链接寄存器（返回地址）

# 读取 CFSR（可配置故障状态寄存器）
(gdb) x/1xw 0xE000ED28

# 读取 HFSR（硬故障状态寄存器）
(gdb) x/1xw 0xE000ED2C

# 读取故障地址寄存器
(gdb) x/1xw 0xE000ED34
```

HardFault 常见触发原因：
- 非对齐内存访问
- 访问未映射的内存空间
- 除零运算错误
- 栈空间溢出

### 技巧二：GPIO 状态实时查看

```bash
# 读取 GPIOA 的 IDR（输入数据寄存器）
(gdb) x/1xw 0x40010808

# 读取 GPIOA 的 ODR（输出数据寄存器）
(gdb) x/1xw 0x4001080C
```

### 技巧三：变量值强制修改

```bash
# 修改变量值
(gdb) set variable my_counter = 100

# 修改寄存器值
(gdb) set $r0 = 0x12345678

# 修改指定内存地址值
(gdb) set {int}0x20000000 = 42
```

### 技巧四：反汇编分析

```bash
# 反汇编当前函数
(gdb) disassemble

# 反汇编指定函数
(gdb) disassemble main

# 启用源代码与汇编混合显示
(gdb) set disassemble-next-line on
```

### 技巧五：调试会话保存与恢复

**保存断点与监视点配置：**

```bash
(gdb) save breakpoints breakpoints.txt
```

**恢复已保存配置：**

```bash
(gdb) source breakpoints.txt
```

### 技巧六：远程调试模式

当 OpenOCD 服务运行于远程主机时，执行以下连接命令：

```bash
# 在 GDB 中连接远程 OpenOCD
(gdb) target extended-remote 192.168.1.100:3333
```

### 技巧七：批量测试脚本

创建 GDB 脚本文件 `test.gdb`：

```gdb
target extended-remote localhost:3333
monitor reset halt
load
break main
continue
next 10
info locals
quit
```

执行脚本：
```bash
arm-none-eabi-gdb control.elf -x test.gdb
```

## 八、参考命令汇总

### GDB 常用命令表

| 命令 | 缩写 | 功能说明 |
|------|------|---------|
| `run` | `r` | 启动程序执行 |
| `continue` | `c` | 继续执行 |

| `step` | `s` | 单步进入 |
| `finish` | - | 跳出当前函数 |

| `watch` | - | 设置监视点 |

| `info` | `i` | 查看各类信息 |
| `backtrace` | `bt` | 查看调用栈 |
| `quit` | `q` | 退出 GDB |

### OpenOCD 常用命令表

在 GDB 中通过 `monitor <命令>` 格式调用 OpenOCD 命令：

| 命令 | 功能说明 |
|------|---------|
| `monitor reset halt` | 复位目标并停止 |
| `monitor reset run` | 复位目标并运行 |
| `monitor halt` | 暂停 CPU 执行 |
| `monitor resume` | 恢复 CPU 执行 |
| `monitor flash info 0` | 查看 Flash 信息 |
| `monitor reg` | 查看寄存器组 |
