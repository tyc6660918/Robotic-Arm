# STM32 开发工作流程规范

本规程规定完整的 STM32 与 STM32CubeMX 开发循环操作要求。

---

## 一、标准开发流程

```
需求分析
   ↓
STM32CubeMX 图形化外设配置
   ↓
生成初始化代码
   ↓
Visual Studio Code 编写业务逻辑
   ↓
编译构建
   ↓
调试（OpenOCD + GDB）
   ↓
功能验证
   ↓
代码提交
```

## 二、外设配置（STM32CubeMX）

### 打开现有工程

```bash
# 定位 .ioc 工程文件
robots/Dummy-Arm/firmware/stm32-control/control/control.ioc

# 使用 STM32CubeMX 软件打开该文件
```

### 配置操作步骤

1. **Pinout & Configuration（引脚与外设配置）**——选择外设、分配引脚功能
2. **Clock Configuration（时钟树配置）**——配置系统时钟树
3. **Project Manager（工程管理）**——设置工程名称与输出路径
4. **Generate Code（生成代码）**——输出初始化代码

### 用户代码保护规则

STM32CubeMX 在重新生成代码时，将保留位于 `USER CODE BEGIN` 与 `USER CODE END` 标记之间的代码段：

```c
/* USER CODE BEGIN 0 */
// 此处代码受保护，不会被 CubeMX 覆盖
int my_variable = 42;
/* USER CODE END 0 */
```

## 三、业务逻辑编写（Visual Studio Code）

### 推荐代码组织方式

```c
// main.c
int main(void) {
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_TIM2_Init();

    /* USER CODE BEGIN 2 */
    App_Init();  // 应用层初始化入口
    /* USER CODE END 2 */

    while (1) {
        /* USER CODE BEGIN 3 */
        App_Loop();  // 应用层主循环入口
        /* USER CODE END 3 */
    }
}
```

### 独立应用文件结构

```
Core/
├── Inc/
│   └── app_main.h      # 应用层头文件
└── Src/
    └── app_main.c      # 应用层实现代码
```

## 五、调试规程

### Visual Studio Code 图形界面调试

```
F5 快捷键  →  自动执行编译 + 烧录 + 启动调试
```

### 常用调试操作

| 快捷键 | 功能 |
|--------|------|
| `F5` | 继续执行 |
| `F10` | 单步跳过（Step Over） |
| `F11` | 单步进入（Step Into） |
| `Shift + F11` | 单步跳出（Step Out） |
| `Shift + F5` | 停止调试 |

### 变量监视

- 左侧"变量"面板自动显示当前作用域的局部变量
- 右键单击变量，选择"添加到监视"可实现持续跟踪

### 外设寄存器查看

- 左侧"外设"面板展开对应外设节点，查看寄存器当前值

## 七、外设配置修改流程

### 应用场景：新增定时器外设

**步骤 1：启动 STM32CubeMX**

```bash
# 打开 .ioc 工程文件
STM32CubeMX → Open Project → control.ioc
```

**步骤 2：配置新增外设参数**

```
Pinout & Configuration → Timers → TIM3
  - Mode: PWM Generation CH1
  - Prescaler: 71
  - Counter Period: 999
```

**步骤 3：执行代码生成**

```
Project → Generate Code
```

**步骤 4：在 Visual Studio Code 中补充业务逻辑**

```c
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 500);  // 占空比设为 50%
/* USER CODE END 2 */
```

**步骤 5：执行编译、调试与功能验证**

## 八、版本控制工作流

### 新功能开发流程

```bash
# 1. 创建功能分支
git checkout -b feature/add-motor-control

# 2. 开发与测试
# ... 编码过程 ...

# 3. 提交代码
git add Core/Src/motor_control.c
git commit -m "feat: Add motor PWM control

- Implement motor speed control via TIM3 PWM
- Add safety current limiting
- Tested with 42 stepper motor

Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>"

# 4. 推送分支并创建合并请求
git push -u origin feature/add-motor-control
gh pr create
```

### 禁止提交的文件类型

```
build/           # 编译构建产物
*.axf *.hex      # 二进制可执行文件
*.uvguix.*       # Keil 用户配置文件
__pycache__/     # Python 缓存目录
```

## 九、故障排查清单

### 编译失败

- [ ] 交叉编译工具链是否正确安装
- [ ] Makefile 路径配置是否正确
- [ ] 缺失的头文件是否已包含

### 烧录失败

- [ ] OpenOCD 是否能建立与目标芯片的连接
- [ ] SWD 线缆连接是否正确
- [ ] 开发板是否已接通电源

### 程序未启动运行

- [ ] BOOT0 跳线帽位置是否正确
- [ ] 是否触发 HardFault 异常（检查串口输出）
- [ ] 外设时钟是否已使能

### 外设功能异常

- [ ] 外设时钟是否已使能（检查 RCC->APBxENR 寄存器）
- [ ] GPIO 引脚配置是否正确
- [ ] 中断是否已使能（检查 NVIC 配置）
- [ ] 引脚是否存在复用功能冲突


